# Atividade Avaliativa: Tabela Comparativa de Metodologias

## 📋 Descrição do Desafio
Este documento apresenta uma análise comparativa detalhada entre os modelos de desenvolvimento **Ágil** e **Cascata (Waterfall)**, com foco estratégico na execução de testes de software, suas respectivas vantagens e limitações.

---

## 📊 Quadro Comparativo: Ágil vs. Cascata

| Critério de Análise | Metodologia Ágil (ex: Scrum / XP) | Modelo Cascata (Waterfall) |
| :--- | :--- | :--- |
| **Abordagem dos Testes** | **Contínua e Integrada:** Os testes ocorrem em paralelo com o desenvolvimento a cada Sprint. | **Fase Linear e Tardia:** Os testes ocorrem estritamente após a conclusão de toda a codificação. |
| **Papel do QA / Testador** | **Membro Ativo do Time:** Colabora desde o refinamento de requisitos até a entrega final. | **Executor de Fase:** Recebe o software pronto e valida com base em documentação prévia. |
| **Foco Estratégico** | **Prevenção de Defeitos:** Identifica falhas cedo através de testes unitários e automação. | **Detecção de Defeitos:** Encontra bugs em massa acumulados ao longo de todo o projeto. |
| **Vantagens Principais** | <ul><li>Feedback rápido do cliente</li><li>Correção de bugs barata</li><li>Maior flexibilidade a mudanças</li><li>Testes de regressão frequentes</li></ul> | <ul><li>Escopo e prazos bem definidos</li><li>Fácil mensuração de progresso</li><li>Documentação robusta e detalhada</li><li>Ideal para requisitos estáveis</li></ul> |
| **Limitações e Riscos** | <ul><li>Falta de tempo para documentação exaustiva</li><li>Dependência alta de automação</li><li>Risco de perda de escopo (Scope Creep)</li><li>Exige forte alinhamento do time</li></ul> | <ul><li>Alto custo para corrigir erros de design</li><li>Feedback tardio do usuário final</li><li>Bugs complexos descobertos no fim</li><li>Inflexível a mudanças de mercado</li></ul> |

---

## 🔍 Conclusão dos Modelos de Teste

* **No Modelo Ágil:** O teste é um **hábito diário** focado em qualidade contínua. É ideal para produtos modernos, dinâmicos e que precisam de lançamentos frequentes no mercado.
* **No Modelo Cascata:** O teste é um **portão de controle** rigoroso. É ideal para sistemas críticos (como softwares médicos ou bancários tradicionais) onde os requisitos não podem mudar e o planejamento precisa ser cirúrgico.
